# Where Tamandua stands

The one-page map. Read this before anything else in `docs/`.

Last updated 2026-08-27 (real-source launch and post-fork bug fixes verified).

---

## What this is

A **facts-only index of SWAT+ Fortran source**, delivered two ways: a 14-tool
MCP server, and a generated file in the checkout. Both answer the same
questions — which routine reads this file, what calls this, what assigns this
variable, what loops are here, where do I set a breakpoint — from static
analysis, with nothing written by a model.

The point is to make **whatever assistant a developer already uses** cheaper
and more accurate on SWAT+, not to be an assistant.

| Live reload | one running process picked up a replaced facts file on its next request |

| Output reader vs. independent `awk` | exact match on real Ames data |

`index_experiment.md` and `output_reader_experiment.md` carry the method and
the caveats for these.

**Verified on real source 2026-08-27.** The pinned parser handles the complete
648-file SWAT+ 62.0.0 tree, and the frozen navigation evaluation is 12/12.
Still unverified against the new scanner: the eight-question byte comparison
(grep 194,675 B · index 11,639 B) and the field-doc coverage figure (4,003 of
6,904), both measured with swatplus-doc-builder.

## What real sessions showed

Run in VS Code against a live SWAT+ checkout, four frozen questions, fresh
chat each, tool calls counted from session transcripts rather than self-report
(`scripts/session_usage.py`). Directional only — one run per cell, and the
comparison arms were measured before several fixes landed, so the counts are
not worth restating. What survived is not about totals:

**Where an assistant failed without these tools, it failed silently.** Asked
for the loops in `hru_control`, it read the 890-line source and produced a
well-formatted table of 18, missing three, including the one at line 152.
Nothing in the answer flagged the gap. That is the failure mode the index
removes — an exhaustive question is exhaustive by construction.

**Plain grep is stronger than expected.** It solved file-to-writer unaided,
chasing a unit number across files with no single line containing both. Claims
that it could not were wrong.

**Availability is not adoption.** Tools present but unmentioned got used
erratically; an explicit "prefer these tools" line in the instruction file is
what changed behaviour — observed on both Claude Code and Copilot. The
instruction, not the transport, is the lever.

Untested: whether weak/local models respond to that instruction the same way
(`ant_integration.md` has the harness, never run against real endpoints).

## What exists

- `tamandua/index/` — parse, render, install pointers, snapshot, scope
- `tamandua/mcp/server.py` — 14 read-only tools over the same objects
- `tamandua/mcp/client.py` — generic MCP stdio client
- `tamandua/output/reader.py` — query a run's output, refuses files it cannot index safely
- `swatplus-build` — writes `swatplus-facts.json` (the MCP server's input,
  and what a release publishes); `--markdown` adds the greppable rendering and
  the instruction pointers for tools that cannot run a server

## Open, in priority order

1. **Weak models.** Everything was measured on the model least likely to need
   the tools. Composing `grep -E '^[^|]+\|open\|unit=107\|'` is a skill;
   calling `file_io("x")` is not. `scripts/test_ant_model.py` is built and
   unit-tested against a mock; it has never run against a real endpoint.
2. **`search_fields` against a real question.** SWAT+ documents 4,003 of its
   6,904 derived-type fields inline (`mm | recharge entering aquifer`), so
   "lateral flow" reaches `aquifer_dynamic%flo` by substring match on parsed
   source. If that holds in a session it addresses the concept-to-identifier
   gap. Untested.
3. **`breakpoint` in anger.** Built, tested, never used to debug anything real.
4. **Isolate one confound.** Copilot's calls on Q2 dropped from 7 to 2 after
   two changes landed together — the instruction pointer and the tool
   descriptions that state results are exhaustive. Which one did it is unknown.
5. **Regenerating dataselector's enrichment.** Its column meanings come from
   overlays generated by this repo's former parser, merged by hand and
   committed; nothing re-runs it when SWAT+ moves. Note that
   swatplus-reference-corpus now ships `schemas/releases/swatplus-62.0.0.json`
   — 145 input files, source-derived and stamped with the commit Tamandua pins —
   which may answer this better than a refresh would.

## Resolved

**Distribution.** The parser is separate (`swatplus-reference-corpus`, and
`swatplus-doc-builder` before it), so this used to be unusable by anyone
outside the team. The facts file splits
building from serving: the parser is now a build-time dependency only, and the
release workflow publishes a JSON the server answers from with neither the
parser nor a SWAT+ checkout present. See [D-8](decisions.md).

## The chatbot

An earlier design — router, retrieval over three corpora, agent loop, answer
assembly with citations, model providers, a CLI and a hosted MkDocs widget —
was built, tested and removed on 2026-08-26. It works; it is simply not this,
and it is meant to be revisited.

It does not live in this repository's history. The last commit containing it
whole is **`222092d`** in the **archived** predecessor, https://github.com/tugraskan/SWATPLUS-TACI, which keeps that
history readable:

## Worth carrying forward

Eight defects in this work were found by ordinary use and none by any harness: an
ambiguous column that cost eight tool calls, a variable index keyed on the wrong
thing, a dead `python -m` entry point, a correct tool result that read as a
failure, a dropped column in heterogeneous rows, and 159 files miscounted from a
missing loop form, input files keyed by expressions instead of their source
defaults, and a long-running server that kept serving its startup snapshot.

Every one was invisible to measurement and obvious within one real question.
The two post-fork fixes were adapted from archived commits `c5fa088` (live
freshness) and `8760e3d` (input filenames); Tamandua also retains its stronger
parser-level input resolution at the pinned parser commit.
